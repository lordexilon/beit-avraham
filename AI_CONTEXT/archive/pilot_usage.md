# Operación del piloto (N11)

Preparación, no experimento ejecutado. `node scripts/pilot_fixtures.cjs` genera una sola vez el padrón de 15 pares y 30 directorios bajo AI_CONTEXT/pilot/workspaces. Se rechaza sobrescribir el manifest. Cada par comparte hashes, tarea y aceptación; alterna orden control/SCA. Los tres casos por categoría tienen variantes pequeñas: hay riesgo de aprendizaje y no son muestras independientes de proyectos. Registrar ese límite en el informe.

N12 debe iniciar cada ejecución en una conversación independiente, mismo modelo exacto y políticas. Control no carga instrucciones, memoria ni herramientas SCA; usa únicamente el fixture y TASK.md. SCA usa la versión de framework indicada, en copia aislada. No ejecutar control desde esta conversación que ya conoce SCA. Documentar preparación de SCA y evitar compartir resultados o soluciones. El generador deja ambos brazos iguales: activar SCA en el brazo correspondiente es parte de la preparación medida, no ocurre automáticamente.

Antes de cada ejecución usar `node scripts/pilot_results.cjs verify-starter bugfix-1 control`, fijar modelo, presupuesto y tiempo límite, registrar reloj/humano y fuente de tokens aislada. El verificador comprueba archivos congelados; directorios agregados también deben revisarse para excluir contaminación. Las mediciones del workflow de N11 representan preparación del mecanismo, no resultados del piloto. Las referencias de Matrix solo se crearán durante N12 con evidencia real.

Pruebas automáticas tras una solución: `node scripts/pilot_results.cjs check bugfix-1 sca`. Guarda salida/exit code/hashes en evidence y devuelve test_run y sha256. El comando exige que acceptance.cjs permanezca congelado. No modifica el código. Tests de navegador y revisión manual siguen siendo necesarios donde TASK.md lo indique. La puntuación es revisión humana documentada, no una certificación automática de calidad.

Completar un JSON según pilot/result_template.json. null significa desconocido. evidence_files contiene rutas relativas al piloto y hashes SHA256 de logs, diff, capturas y revisión. `node scripts/pilot_results.cjs record archivo.json` valida alcance y evidencia y guarda una sola vez; no escribe Matrix. Accepted requiere pruebas automáticas aprobadas sobre el código actual y checks manuales completos. Failed/timeout/abandoned se registran también con evidencia y rúbrica; no declararlos Accepted para completar datos.

`node scripts/pilot_results.cjs report` genera report.json con todos los pares, cobertura del padrón completo y deltas válidos por dimensión, mediana y rango. Rechaza como comparación válida datos sintéticos, modelos/entornos/políticas distintos, sesiones compartidas, ejecución solapada y calidad menor en SCA. Tokens sin exclusividad y costos sin fuente/criterio siguen null. Validar hashes no prueba por sí solo que una medición declarada sea verdadera: auditar logs originales antes de cargar las evaluaciones de ahorro en Matrix.

Alcance de fixtures: desarrollo usa un DOM mínimo para comprobar contrato de selección/notas, con navegador manual para accesibilidad/responsive; refactor tiene revisión estructural; instalación es un ejercicio pequeño de bootstrap. El último no reproduce el instalador original ni conecta Matrix: la certificación del instalador real exige un ensayo adicional aislado con API/UI/capturas. No presentar ese ejercicio como validación operativa del framework.

El recolector no calcula tarifas ni importa importes. Codex/Antigravity suscripción: cuota asignada solo con importe/período/criterio. Ollama: costo de operación separado del cargo API. Reportar ahorro de ejecución y costo total de preparación/mantenimiento; no convertir ahorro de tokens en ahorro de factura de suscripción.
